# 轻量音频转谱（Beta）

使用 Spotify Basic Pitch 1.0.1 与 TensorFlow.js 3.21.0，默认在独立桌面窗口的本机 CPU 上计算，复用系统 Microsoft Edge WebView2 Runtime 与 .NET Framework 4.6.2+，不打开默认浏览器。页面、脚本、官方未修改模型、单线程 WASM/SIMD 及许可约 2.33 MB；无需 GPU、Python、Node 或账号，不随包分发浏览器内核。新增窗口宿主与 SDK 约 0.85 MB，连同转谱资源合计约 3.18 MB。系统没有 WebView2 时窗口会提示原因，可手动使用“文件 → 轻量转谱（浏览器兼容）”；不会静默安装运行时。WASM 不可用时自动回退到 JavaScript CPU。此大小为新增磁盘资源，不是运行内存。

## 使用

1. 点击“音频转谱 · Beta”，或把音频拖到桌面左侧小型“拖入音频 / 曲谱”区域。MIDI、MusicXML 拖入后直接载入曲谱；音频交给独立桌面转谱窗口。窗口文件区可点击选择音频；主窗口左侧拖入区继续支持音频/曲谱。重复打开会唤回原窗口。
2. 源文件最多 64 MB / 10 分钟，每次最多识别 3 分钟。建议先试 15–30 秒；起止使用秒数，终点留空表示最多 3 分钟。格式取决于浏览器解码支持，失败时改用 WAV / MP3。
3. 默认“均衡保留和弦”抑制较弱识别。“多保留弱音”降低阈值并容许更短音，可能增加泛音、杂音和重复音，属于可选实验。“突出旋律”进一步筛弱音，也会减少真实和弦，并非人声分离。
4. 和弦听起来有轻微错位时，可选“轻微对齐和弦起音”：把同一 24 毫秒窗口内、不同音高的起音对齐到最早一音，保留原松音时间与力度。窗口固定在首音，避免连续吸附；重复同音、与同音延音冲突的组保持不动。默认关闭，分解和弦、装饰音应保持关闭。
5. 开始后显示阶段、进度、已用时和动态剩余时间；前几个推理窗口用于测速，加载、保存和停滞阶段不伪造精确倒计时。可切换窗口，请保持工作台与转谱窗口打开。
6. 成功后后台保存 MIDI，自动加入工作台左侧“曲目架”并载入，页面显示导入状态；不用先下载再手动导入。主窗口最小化时也会处理，重启后曲目架保留已生成的曲谱。若结果到达时正在演奏，先加入曲目架，演奏结束后自动载入，不打断当前曲目，也不自动开始弹奏。
7. 转换完成后仍自动下载到系统“下载”文件夹，同名文件追加序号。手动点击“下载 MIDI”、候选谱或对齐前谱时，桌面窗口弹出“另存为”，可选择目录和文件名，覆盖已有文件需确认；取消不影响工作台副本。保存成功后页面显示结果，悬停提示可查看完整路径。同一窗口会记住本次会话最后选择的目录。
8. 浏览器兼容模式自动下载遵循浏览器设置；手动另存优先使用浏览器的文件选择器。不支持该接口的浏览器仍使用普通下载，并提示在浏览器中启用“下载前询问保存位置”。工作台自动导入不依赖任何一次下载是否成功。刷新同一会话页面也能重新下载最后结果，每个结果链接固定对应自己的文件。

桌面拖入的音频仅由本机随机会话路径交给窗口内的 WebView2；直接选中的音频在该组件内解码。窗口不是完整浏览器，不提供任意网页导航、宿主对象或通用文件读写桥接；页面资源仅允许当前本机会话。两者均不发送给外部网站。返回桌面的是音符、文件名、散列与处理参数。页面提醒合法合理使用输入与结果；无需额外填写来源声明，也不声称已核验用户授权。

桌面使用 Windows Shell 文件拖入，仅导入控件接收文件消息，支持普通 Explorer 向提权工作台拖入；未修改系统或进程全局过滤规则。使用者已确认此前 MIDI/音频拖入交接正常，本轮将音频目标切换为独立窗口。一次一个文件，演奏或转谱忙碌时不替换输入。若环境不支持拖入，点击该区域仍可打开文件选择。

## 保存、取消和兼容

个人数据目录 `light-transcriptions/任务编号/` 保存：

- 曲名 `_轻量Beta.mid`：按当前选项处理后的结果。
- `model_selected.mid`：当前识别预设产生、尚未对齐的 MIDI。
- `model_raw.mid`：较宽松的诊断结果，含额外恢复策略，并非可靠真值，也不保证是所选结果的严格超集。
- `provenance.json`：输入片段、处理预设、阈值、对齐统计与散列。

旧结果不会被新任务覆盖。取消或关闭桌面转谱窗口会终止 Worker，并立即撤销未完成任务；浏览器异常消失且未通知桌面时，忙碌租约最多约 120 秒超时。延长租约避免后台标签页计时器降频导致任务中断。未完成曲谱不会自动导入，也不会自动开始游戏演奏。

页面采用左右分栏，小窄窗改为“音频与设置 / 进度与结果”切换。1280×720、1000×650、900×600 的最终结果页已在真实 WebView2 中确认无滚动、面板溢出或页脚遮挡；不保证任意极小窗口、大字号或高缩放均无需滚动。

## 音乐质量与验证范围

清晰单乐器优先；复杂混音、人声、踏板、原曲音色、动态与弯音无法完整还原。输出单条钢琴音轨，不提供多乐器分离。结果页显示候选、当前与起音对齐音数，并可下载“候选谱（可能含误判）”和“起音对齐前”作对照；这些数量不等于正确率。较宽松预设在六份短句中增加了额外音，并未普遍提高匹配分数，因此默认仍保持均衡模式。无需对每首歌手工写谱，但不能保证每首都无需试听或选择预设。

本机六份合成短句的 Node 检查中，WASM 相比 JS CPU 耗时约缩短到 1/6.5–1/9；两后端的所选音高、起音、时长逐项一致，模型释放后 Tensor 数为 0。仅为本机短句基准，不承诺所有电脑或整曲同样提速。加速不修改模型、阈值或音乐时序。初始化缺失/失败、运行中失败、CPU 失败的回退策略检查通过；整套共用流程的真实缺失 WASM 故障回退已检查，通过同一 WAV 的 CPU/加速输出逐字节一致。新增 WebView2 窗口已实际运行生产 Worker：同一 arpeggio 短句生成 20 音，与此前 JS CPU/WASM 基准一致。

实际游戏还有音域折回、同音合并、单旋律模式删和弦等变化。独立钢琴使用全局 Shift，混合黑白键和弦仍约分组错开 55 毫秒；吉他钢琴模式没有这项限制。详见 [音频质量排查](AUDIO_QUALITY_1.5.md) 与 [基准](AUDIO_BENCHMARK.md)。

## 构建与许可

- [Spotify Basic Pitch TypeScript](https://github.com/spotify/basic-pitch-ts)：固定 npm 1.0.1，Apache 2.0，官方模型不改权重。
- [TensorFlow.js](https://github.com/tensorflow/tfjs)：固定 3.21.0 的 core/converter/CPU/WASM，移除 GPU 和 layers。WASM 依赖通知、全文与固定源码位置保留在 `tools/light_audio_web/wasm-notices.txt`，合并分发于 `assets/light_audio/licenses.txt`。
- 在 `tools/light_audio_web` 执行 `npm ci`、`npm run build`；Node 与 node_modules 仅用于开发。生成清单逐文件 SHA-256 校验，组件预算 4.5 MB。
- `node test.mjs` 检查 ETA 与兼容回退。开发基准：`node build.mjs --benchmark <已生成短句目录> wasm detail`；也可用 `cpu polyphonic`，短句生成见 `tools/create_light_audio_benchmark.py`。

高级分离与 MuScriptor/GAME 保留为独立引擎功能，不自动安装或打入轻量包。软件和模型许可不自动授予音乐输入和输出的传播权。


## 桌面窗口的构建

窗口源码在 `tools/audio_window/AudioWindow.cs`，本项目代码为 MIT。固定 NuGet Microsoft.Web.WebView2 1.0.2903.40，SDK 的 BSD 许可及 NOTICE 原文随 `assets/audio_window` 保留。只分发 Core、WinForms 和 x64 Loader，系统 Evergreen Runtime 与 .NET Framework 由 Windows 提供，不将其内核打入 ZIP。WebView2 自身有缓存和运行内存，缓存位于个人数据目录 `light-window/profile`，不属于模型文件或应用解压大小。

`python tools/build_audio_window.py` 使用 Windows 的 .NET Framework C# 编译器，固定 NuGet 包 SHA-256 后构建宿主；SDK 仅缓存到被忽略的 .build。`build_windows.py` 在源码哈希变化时重建，始终检查宿主资源哈希。网页兼容入口继续可用，音频识别仍使用同一小模型，未接入高级引擎或 GPU。

桌面和浏览器兼容入口调用同一 pipeline.js，不各自实现解码或保存。完整整合状态、实测证据与实机边界见 [INTEGRATION_1.5.md](INTEGRATION_1.5.md)。
