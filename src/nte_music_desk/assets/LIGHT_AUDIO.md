# 轻量音频转谱（Beta）

1.5 开发版新增，使用 Spotify Basic Pitch 1.0.1 和 TensorFlow.js 3.21.0 的 CPU 组件。计算脚本、页面、未修改的官方模型及许可证约 1.51 MB，不到上一份约 49 MB 解压工作台的十分之一。此数字为新增磁盘资源，不是运行内存；复用已安装的浏览器，不附带 Python、Node、PyTorch、WASM 或浏览器内核。

## 使用流程

1. 点击左侧“音频转谱 · Beta”或“文件 → 轻量音频转谱”。软件会在默认浏览器打开本机页面，需要保持工作台运行。
2. 选择自己的本地音频文件即可转换，无需填写素材使用依据或来源说明。页面保留简短的合法使用提醒。音频只在该标签页计算，不上传给外部网站；回到工作台的内容只有音符、文件名、散列和本地文件记录，不将本地文件标记为已核验授权。
3. 先试 15–30 秒。源文件最多 64 MB / 10 分钟，每次最多识别 3 分钟。起止时间使用秒数，终点留空表示从起点最多识别 3 分钟。解码格式由当前浏览器支持决定，失败时可改用 WAV / MP3。
4. “保留和弦”保留模型识别的多音。“突出旋律”进一步抑制较弱的音，可能减少真实和弦；它不是人声分离或可靠的主旋律识别。生成后自动导入工作台，先试听，再选择乐器和游戏试奏。

可以取消计算；关闭页面或工作台后，未完成曲谱不会导入。关闭标签页后，工作台中的忙碌状态最多约 8 秒后解除。断开工作台连接会停止页面中的计算。无网络也可使用：全部资源由本机 127.0.0.1 提供，没有 CDN 或在线模型下载。浏览器可能有自己的网络活动，不属于转谱页面的请求。

每次成功结果保存于个人数据目录 light-transcriptions/任务编号，包含选中方式的 MIDI、model_raw.mid 和 provenance.json。原始识别结果不覆盖，识别保留开头休止与共同片段时间基准，曲谱本身从片段 0 秒开始；原文件起点另记在来源记录。不会自动开始游戏演奏。平均激活值仅用于力度/弱音筛选，不是校准过的正确概率。

## 适用范围和质量

适合清晰的单乐器录音，支持和弦。复杂原唱、人声和伴奏的独立声部、踏板、原曲音色与弯音不在轻量模式的完整还原范围内。输出一条钢琴音轨；它不具备 MuScriptor 的多乐器分轨能力。

已在真实浏览器完成自制钢琴短句 → Worker CPU 识别 → 本机 MIDI → 桌面自动导入。20 音短句匹配 20 音、额外 4 音，音高/起音 F1 为 90.9%；这不是原曲还原率、逐音正确率或任意歌曲的 90–95% 承诺。更多合成短句仍存在明显波动；本轮用于参数比较的样本不算独立泛化验收。详见 AUDIO_BENCHMARK.md。

高级分离、MuScriptor 和 GAME 保留在“文件 → 高级音频处理（独立引擎）”，需独立安装、更多磁盘空间及相应模型条款。轻量入口不会替你安装这些组件。

## 来源和构建

- [Spotify Basic Pitch TypeScript](https://github.com/spotify/basic-pitch-ts)：Apache 2.0，模型取自固定 npm 1.0.1，不修改权重。
- [TensorFlow.js](https://github.com/tensorflow/tfjs)：CPU/core/converter 为 Apache 2.0。构建移除 layers、GPU 后端、WASM 和未用的推理包装；依赖通知及全文在 assets/light_audio/licenses.txt。
- 开发者在 tools/light_audio_web 执行 npm ci，然后 npm run build。Node 和 node_modules 只用于开发构建，不向使用者分发。固定依赖和锁文件随源码提供；生成清单逐文件 SHA-256 校验，总组件预算 4.5 MB。

软件和模型的开源许可不自动授予输入音乐及其输出的传播权，继续使用本项目的本地素材许可说明。
