# 本地音频转谱（v1.4.0，可选）

仅处理用户主动选择的本地音频，不提供搜曲或音乐下载。默认用 MuScriptor 0.3.0 识别已有伴奏 / 纯音乐的多轨音符；GAME 1.0.3 的歌声主旋律为独立 Beta，不自动替换伴奏。

原唱自动分离伴奏暂缓开放：先前 ViperX 分离模型的权重许可尚未核实，下载和调用均已禁用。请提供已获必要授权的伴奏，或单独试用主旋律 Beta。详细边界见 [音乐与模型许可](COPYRIGHT_AND_MODELS.md)。

## 准备引擎

1. 安装完整 Python 3.10–3.13（推荐 3.12），打开“音频转谱 → 引擎配置与检查”。便携软件自身不含开发环境或 ML 权重。
2. 选择生成内容，再点“安装 / 更新独立引擎”，选择该 Python 的 python.exe。引擎在个人数据目录独立创建，保留原环境。仅主旋律 Beta 安装较轻依赖；伴奏需要 PyTorch 等较大组件。需 NVIDIA 版本时先选择 NVIDIA GPU 再安装；驱动不兼容时改用 CPU。
3. 阅读对应模型完整条款。MuScriptor 权重为 CC BY-NC 4.0 加附加条件，GAME 权重为 CC BY-NC-SA 4.0，均有非商业限制；代码 MIT 不替代权重许可。用户自行在 MuScriptor 的 Hugging Face 页面接受条款，本工具不代为确认。
4. MuScriptor 需要在独立引擎的终端登录一次，例如：

```powershell
& "$env:LOCALAPPDATA\NteMusicDesk\audio-engine\Scripts\hf.exe" auth login
```

令牌只交给官方登录程序，不发送到聊天、工作台配置或 GitHub。不需要配置 Git 凭据。GAME 不需要 HF 登录，但下载或使用前仍需确认其条款。

已有独立环境时，选择其 Python 解释器；此新流程不接受 muscriptor.exe。点击“检查环境”查看依赖、解码器、GPU 及模型登录/缓存状态。缓存存在不代表已核验输入音乐权限。

## 每次使用

1. 选择 WAV、MP3、FLAC、OGG、M4A 或 AIFF，最大 512 MB。填写起止时间（支持 分:秒），终点留空为整段；单次最多 30 分钟，首次建议 15–30 秒。
2. 已有伴奏选择“伴奏（默认）”；歌声旋律选择“仅主旋律（Beta）”，可以选择歌声语言。medium 为伴奏默认模型；small 较省资源，large 较占资源。主旋律 Beta 使用小型 ONNX 模型并在 CPU 运行。
3. 选择素材使用依据，填写原创录音说明、许可链接或授权记录，再确认本次所用模型条款。确认项默认不选，来源记录不等于取得授权；视频发布、曲谱分享和商业用途另行核对。
4. 开始生成。处理在本机独立子进程运行；依赖和首次获取模型需要联网。可取消任务，取消终止本任务进程树，未完成结果不自动导入。
5. 有效 MIDI 自动导入工作台。可试听选段原音频，查看多轨、静音或指定角色，再适配游戏音域。转谱不会自动开始游戏演奏。

## 文件与质量边界

每次任务保存到个人数据目录 transcriptions/任务编号，包含解码后的选段 WAV、<原文件名>_伴奏.mid 或 <原文件名>_旋律Beta.mid、来源与模型记录、令牌遮盖后的日志尾部。记录包括输入散列、原曲选段偏移和用户填写的使用依据，可能包含用户的私人说明；不要直接把整个目录上传 GitHub。文件在本机保留，请自行按需清理。

伴奏保留多乐器声部与原始起音，不强制只识别钢琴、不网格量化或删掉开头休止。工作台后续才做游戏音域与键位适配；Beta 旋律保留相同的选段时间基准。音色变为游戏钢琴不代表音高识别一定正确。

本轮离线测试覆盖多轨结果、片段时间、取消、坏输出拒绝、输入说明与模型确认、禁止不明许可权重调用。MuScriptor 真实模型质量尚未验收；GAME 的原型推理已跑通，尚需许可明确的歌声样本评估识别质量。复杂混音、合唱、滑音、打击乐和音域折回都会影响还原。游戏琴键不能完整表达踏板、连续力度、原乐器音色，时序试听也不代表游戏实际发声。

官方来源：[MuScriptor](https://github.com/muscriptor/muscriptor)、[MuScriptor 模型](https://huggingface.co/MuScriptor/muscriptor-medium)、[GAME 模型许可](https://github.com/openvpi/GAME/releases/tag/v1.0.0)。
