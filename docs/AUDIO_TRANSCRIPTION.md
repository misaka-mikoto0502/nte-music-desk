# 本地音频分离与转谱（2.0，可选高级引擎）

本页说明“文件 → 高级音频处理（独立引擎）”。左侧轻量转谱 Beta 默认在独立桌面窗口中运行，无需 Python/GPU/账号，提供浏览器兼容入口；模型、脚本等约 2.33 MB，窗口宿主及 SDK 另约 0.85 MB。详见 [轻量转谱](LIGHT_AUDIO.md)；它不提供人声分离或多乐器分轨。

仅处理用户主动选择的本地音频，不提供搜曲或音乐下载。默认用 MuScriptor 0.3.0 识别已有伴奏 / 纯音乐的多轨音符；GAME 1.0.3 的歌声主旋律为独立 Beta，不自动替换伴奏。

考虑音乐版权风险，不提供搜索和下载。请选择你有权处理的本地音频，文件不上传到外部服务器。高级引擎用官方 MIT 许可的 UMX-HQ 分离原唱，旧 ViperX 权重继续禁用。详细边界见 [音乐与模型许可](COPYRIGHT_AND_MODELS.md)。

## 准备引擎

当前仅允许 small（约 0.1B）和 medium（约 0.3B），不提供 large。CPU 可选不等于已在所有无显卡电脑验收；主程序尚未包含音频运行环境。无需用户安装 Python 的可选组件包仍在设计，详见 [部署约束与交付计划](AUDIO_DEPLOYMENT.md)。

1. 安装完整 Python 3.10–3.13（推荐 3.12），打开“文件 → 高级音频处理（独立引擎）”。便携软件不含高级引擎开发环境或权重；轻量 Basic Pitch 小模型单独随包提供。
2. 选择生成内容，再点“安装 / 更新独立引擎”，选择该 Python 的 python.exe。引擎在个人数据目录独立创建，保留原环境。仅主旋律 Beta 安装较轻依赖；伴奏需要 PyTorch 等较大组件。CPU / 自动安装采用 CPU 版 PyTorch；需 NVIDIA 版本时先显式选择 NVIDIA GPU 再安装，驱动不兼容时改用 CPU。
3. 阅读对应模型完整条款。MuScriptor 权重为 CC BY-NC 4.0 加附加条件，GAME 权重为 CC BY-NC-SA 4.0，均有非商业限制；代码 MIT 不替代权重许可。用户自行在 MuScriptor 的 Hugging Face 页面接受条款，本工具不代为确认。
4. MuScriptor 需要在独立引擎的终端登录一次，例如：

```powershell
& "$env:LOCALAPPDATA\NteMusicDesk\audio-engine\Scripts\hf.exe" auth login
```

令牌只交给官方登录程序，不发送到聊天、工作台配置或 GitHub。不需要配置 Git 凭据。GAME 不需要 HF 登录，但下载或使用前仍需确认其条款。

已有独立环境时，选择其 Python 解释器；此新流程不接受 muscriptor.exe。点击“检查环境”查看依赖、解码器、GPU 及模型登录/缓存状态。缓存存在不代表已核验输入音乐权限。

“验证模型访问”在确认所选 MuScriptor 条款后联网检查该模型文件的访问权限，不下载权重；成功不代表模型已加载或识别质量通过。它与“检查环境”的本地依赖检查分别显示结果。

## 每次使用

1. 选择 WAV、MP3、FLAC、OGG、M4A 或 AIFF，最大 512 MB。填写起止时间（支持 分:秒），终点留空为整段；单次最多 30 分钟，首次建议 15–30 秒。
2. 已有伴奏选择“伴奏曲谱（默认）”；含人声的输入在音频类型中选“原唱 / 含人声”，先分离再转谱。“仅分离人声与伴奏”输出 WAV，无需 MuScriptor 登录；“仅主旋律（Beta）”直接识别歌声；“伴奏＋主旋律（Beta）”先分离再双路识别，保留伴奏、旋律、合并三份 MIDI。medium 为伴奏默认模型，主旋律 Beta 在 CPU 运行。
3. 选择素材使用依据，填写原创录音说明、许可链接或授权记录，再确认本次所用模型条款。确认项默认不选，来源记录不等于取得授权；视频发布、曲谱分享和商业用途另行核对。
4. 开始生成。处理在本机独立子进程运行；依赖和首次获取模型需要联网。可取消任务，取消终止本任务进程树，未完成结果不自动导入。
5. 有效 MIDI 自动导入工作台。生成前可点“试听选段”，仅解码最多 30 秒，不加载模型；生成后可在“原音频 / 伴奏 / 人声”间分别试听。仅分离时不导入 MIDI。查看多轨、静音或指定角色，再适配游戏音域；转谱不会自动开始游戏演奏。

分离引擎使用 Open-Unmix 1.3.0，首次获取约 143 MB UMX-HQ 官方权重，无需账号。UMX-HQ 与 MuScriptor、GAME 是不同模型，其安装和授权条件分别判断。所有分离输出保留相同采样数与起点；识别保留同一选段时间基准。合并仅移除与旋律近同时起止的同音重复，原伴奏和旋律文件不改动。旋律 Beta 失败时仍可使用已生成的伴奏，界面会提示失败原因。

生成后点击“对照试听”，可在相同片段位置切换原音频、分离伴奏/人声与曲谱合成音，支持拖动定位、暂停和循环；最多比较选段前 30 秒。界面显示选段内秒数和原音频秒数。曲谱合成使用轻量音色，只用来核对音高、节奏及漏音，不能作为原曲音色还原评分。开始新处理或进入游戏演奏会关闭对照试听。

## 文件与质量边界

每次任务保存到个人数据目录 transcriptions/任务编号，包含解码后的选段 WAV、<原文件名>_伴奏.mid 或 <原文件名>_旋律Beta.mid、来源与模型记录、令牌遮盖后的日志尾部。记录包括输入散列、原曲选段偏移和用户填写的使用依据，可能包含用户的私人说明；不要直接把整个目录上传 GitHub。文件在本机保留，请自行按需清理。

伴奏保留多乐器声部与原始起音，不强制只识别钢琴、不网格量化或删掉开头休止。工作台后续才做游戏音域与键位适配；Beta 旋律保留相同的选段时间基准。音色变为游戏钢琴不代表音高识别一定正确。

离线测试覆盖多轨结果、片段时间、取消、坏输出拒绝、输入说明与模型确认、禁止不明许可权重调用。当前已用自制钢琴采样短句实跑 MuScriptor 和 UMX-HQ，结果见 AUDIO_BENCHMARK.md；这不等于完整歌曲质量验收。GAME 的原型推理已跑通，尚需许可明确的歌声样本评估识别质量。复杂混音、合唱、滑音、打击乐和音域折回都会影响还原。游戏琴键不能完整表达踏板、连续力度、原乐器音色，时序试听也不代表游戏实际发声。
