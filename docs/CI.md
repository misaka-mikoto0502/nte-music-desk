# Windows 自动构建与故障排查

工作流位于 `.github/workflows/build-windows.yml`，PR、版本标签推送或手动运行会触发检查。源码测试先于模型准备，普通测试不需要下载模型；随后准备完整运行资源、打包并进行独立验证。

## 2026-11-09 · 2.0.2 后续 CI 修复

PR #4 与 v2.0.2 标签触发的任务在源码测试阶段失败；原始日志为 176 项检查，20 个断言失败及 14 个错误（含子用例）。多个错误来自同一环境差异，不代表同样数量的独立功能问题：

- 云端 Windows 没有 wave 输出设备，真实 MCI 打开检查失败。自检现在探测设备数，无设备时明确报告 `audio_comparison=not_run_no_wave_output_device`；只跳过依赖实际设备的检查，模拟命令、WAV 合成及其他检查继续执行。有设备时仍检查真实 MCI，真实错误继续报错。
- 英文系统控制台默认使用 cp1252，测试直接输出中文时触发编码异常。工作流显式设置 `PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8`。
- 临时目录使用 `RUNNER~1` 等短路径，而应用将路径解析为完整路径。测试夹具统一 `.resolve()` 后再构造预期值，避免将同一个文件误判为不同文件。

本地从 Git 导出干净源码并叠加本次补丁，不带本地模型目录；使用真实 Windows 8.3 临时目录别名及 UTF-8 环境执行，177 项检查通过。新增检查验证无声卡时不会打开 MCI，并正确记录硬件检查缺失。机器日志保留于 `.build/validation/ci-2026-11-09/`；该结果是本地复现，云端最终结果以修复提交触发的新任务为准。

演奏与转谱算法未改动。本次修复作为 `release/2.0.0` 后续普通提交，保留已推送的 v2.0.2 标签和既有附件，不强制覆盖。

## 推送后查看结果

推送 `release/2.0.0` 后，原 PR 会针对新的提交重新检查。查看最新提交对应的任务，等待全部步骤成功再合并到 main。旧标签对应失败任务保留历史结果；重复运行旧标签仍会读取旧代码。

检查失败时点进 `Details`，展开第一项红色步骤，查看测试末尾的 `FAIL`／`ERROR` 和堆栈。打包失败则查看模型下载、校验或本机组件构建步骤。不要通过删除整个检查或绕过失败来标记通过。
