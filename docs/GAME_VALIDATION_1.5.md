# 1.5 开发版游戏检查 · 2026-10-28

本轮使用项目现有的转换、排程和前台校验演奏后端，在真实《异环》窗口测试。诊断程序只记录既有后端的调用、控制文件和运行报告，不提供另一套输入实现。启动权限由使用者手动确认，之后同一诊断进程内的测试继承权限。

## 钢琴

- 36 键半音阶、2/4/6/8/12 音组、黑白键混合组、重复键与长音间隔组成 84 音测试谱；运行报告为 completed，84 音发送完成。可见琴键有对应反馈，结束后程序持有按键为 0。
- 控制文件暂停后释放按键，两秒后继续恢复演奏；恢复时演奏时间仍在约 3 秒处。约 10 秒处发送停止指令，最终持有按键为 0。这里验证的是工作台控制协议，不等于物理 F7/F8 的实测。
- 轻量转谱样例共 24 音，7.482 秒，运行报告 completed。该结果仅证明识别结果可进入游戏演奏，不是识别准确率或实际发声完整度的测量。
- 使用者重听《小星星》后明确确认听到歌曲。此次重听随后因游戏失去前台焦点而自动停止，没有把听到歌曲记为整首无遗漏验收。

当前按键保持仍采用 300 毫秒配置。长音测试保留曲谱中的时间间隔，不宣称已复现踏板或连续延音。钢琴 C3–B5 的绝对音高尚未通过游戏录音校准；12 音是软件发送上限测试，游戏实际同时发声数仍需录音分析。

- 没有出现失焦、调度超时或异常终止；停止指令的报告已正确区分为“收到工作台停止指令”。实际同时发声数和整首听感不由这些发送计数代替。

## 主窗口与启动追加

普通自动启动未出现窗口；改为直接管理员启动后，使用者确认窗口正确弹出并开始操作。实际看到迷你播放器，运行目录已产生工作台发起的演奏任务、暂停控制命令和停止报告。按键与焦点的完整两组人工操作结果仍等使用者反馈。

发现无界面引导进程在 ShellExecuteEx 返回后立即退出，却未设置 Windows 要求的 SEE_MASK_NOASYNC。现已补全，使 Shell 完成启动交接后再退出，同时拒绝缺失子进程句柄的虚假成功；增加两项回归。该缺项与普通启动现象相符，但修正后普通启动的实际 UAC/窗口仍待复验，不能把直接管理员启动当成复验。
