## 2026-11-19 初始阶段审查

审查日期：2026-11-19。范围为当前源码及本轮累积修改；本次明确进入阶段收尾，允许全局验证和版本归档。结论是五个分页的职责划分仍成立，演奏、全曲调整、片段修改和耗时任务没有必要推倒重做。问题集中在重复计算、重复刷新与异步完成时的状态边界，已修正明确问题；仍然存在的复杂度及后续条件列在下表。

| 区域 | 判断与本轮处理 | 保留的边界 |
| --- | --- | --- |
| 导入与曲目栏 | 点击、拖入和快捷键共用入口；曲谱直接载入，音频进入转谱。设置、曲名和续播位置独立保存，没有再建立第二套曲库。 | 原文件、已保存方案和指定录制目录均保留；从列表移除不等于删除文件。 |
| 演奏页 | 乐器、演奏方案、原谱对照和演奏主操作集中。播放区只在本页占空间，主窗与小窗复用明音进度控件。 | 合成试听用于比较，游戏实际音色和国际服发声仍需实机确认。 |
| 调整页 | 全曲速度、移调、声部及检查导出集中，复杂参数按需展开。与分段页共用乐器和已保存设置，未另建互相冲突的参数体系。 | 声部细节和报告保留辅助窗口，它们不是第二个主工作区。 |
| 分段页 | 先乐器、再选区、再修改和比较，顺序正确。候选与已应用状态分开，撤销重做按曲目／乐器隔离。删除提交后重复触发的一次页面刷新。 | 按原曲起音归属片段，跨段长音不重复；不能只截出短片段再单独计算八度，否则会改变区外结果。 |
| 分段编译 | 原实现每个区间先深复制整首变体，再过滤区外数据，属于可消除的重复工作。改为仅复制本区间事件及变更明细，保留整曲变体缓存和输出语义。 | 不删除转换前校验、保存前校验和排程检查；这些分别保护输入、持久化和演奏边界，不能仅因看起来相似就合并。 |
| 转谱页 | 已是主窗内的 Frame，切页不会销毁任务。模型执行、取消和结果接收分离，后台完成不抢曲。保留已有单任务队列。 | 类名 OfflineAudioDialog 为历史命名，当前实现不是独立窗口；本轮不为改名增加兼容别名或第二条实现路径。 |
| 社区与工程 | 便携工程和真实 HTTP Demo 链路可用。修复下载完成时打断合成／原音频试听、离开社区后仍自动切页、把前一曲说明带入新曲的问题；请求进行中也阻止列表双击改写请求所属曲目。 | 公开服务、账号、审核、举报、配额、备份并未实现，仍明确为 Demo；不能当作已经完成的公共社区。 |
| 背景与滚动 | 背景取景集中在一个协调器，滚动和重新显示集中在一个画布类。删除重复设置的滚动回调；此前临时系统双缓冲已经移除，恢复可见后直接完成 Tk 控件绘制。 | Tk 原生子窗口不支持此处所需的逐控件透明，因此保留背景取样合成；纯色回退用于图片缺失。这两条路径各有实际用途。 |
| 数值与按钮 | 数值静止显示、点击编辑和原生键盘输入复用一个变量；按钮保留原生焦点、禁用和触发行为。 | 不把输入框和按钮全部改成自绘交互；否则要重做键盘、焦点、无障碍及输入法行为。 |
| 状态协调 | 演奏／暂停／停止共用排程，异步结果用任务标识和曲目修订号防止迟到覆盖。移除重复控制刷新和已失效的局部变量。 | App 仍承担较多协调职责。后续增加多个并行编辑任务时，可按任务与曲目会话拆分；本轮不在稳定化末期进行全盘迁移。 |
| 权限与兼容 | 保留启动一次授权；国服／国际服共用进程和窗口类识别，失焦停止与按键释放约束不放宽。 | 自动检查使用替身窗口／调度或离线自检，不替代 UAC 人工确认和真实游戏测试。 |
| 版本材料 | 当前说明、包内帮助、版本号和归档证据统一到 2.1.1。历史验证报告保留原时间与范围，不拿旧包结果证明本次源码。 | 未上传 GitHub，不移动已有标签，不覆盖旧版 ZIP 或指定的 2.0.2 录制目录。 |

## 分段计算的对照

使用自行生成的 5,000 音、64 段、同一演奏变体样例，在同一 Python 环境开启 tracemalloc 进行前后对照。完整 score 的排序 JSON SHA-256 均为 `2f6e9be79b486941b0ad1f0521c8d7ea05bc00175882b2b591ddc821aa5378af`。耗时从 4.3689 秒降至 1.3930 秒，跟踪到的 Python 峰值分配从 5,046,947 字节降至 3,995,987 字节。该样例验证复制开销减少且输出不变，不代表所有乐曲均有相同提速。原始记录为 `.build/validation/2.1.1-stage/arrangement-before.json` 与 `arrangement-after.json`。

## 后续值得投入的方向

优先继续打磨片段比较、真实游戏试听与工程可复现性。多乐器对比、曲目级历史和社区公开化，应分别建立在清晰的参数作用域、工程迁移策略与服务运营能力上。暂不追加第二套编辑器、额外的顶级页面或通用插件框架，也不以更换 GUI 框架代替对现有职责和状态的整理。
