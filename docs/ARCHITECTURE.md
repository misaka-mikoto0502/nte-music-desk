# 项目结构

```text
nte-music-desk/
├── src/nte_music_desk/
│   ├── _bootstrap.py       # 源码与 EXE 共同入口
│   ├── cli.py              # 命令行、演奏调度、合成试听与子进程
│   ├── ui.py               # 主窗口
│   ├── startup.py          # 图形应用启动时提权，离线命令不提权
│   ├── mini_player.py      # 置顶、不激活的小窗、明音进度与下拉换曲
│   ├── playback.py         # 暂停时钟、控制序号与按键恢复
│   ├── backdrop.py        # 共用夜景、浅色面板合成与窗口／滚动适配
│   ├── scrolling.py       # 滚动画面提交、分页内容窗口重新显示
│   ├── appearance.py       # 四色圆角、原生按钮与下拉框皮肤
│   ├── controls.py         # 数值步进、明音速度与进度滑块
│   ├── branding.py         # 完整中文图片字标与显示适配
│   ├── midi.py             # 标准 MIDI 读取、节奏与音域转换
│   ├── performance.py      # 统一按键时序与计划发声音符
│   ├── presets.py          # 按曲谱哈希与乐器保存方案
│   ├── workspace_pages.py # 可滚动页面与固定主要操作区
│   ├── segment_ui.py      # 原曲选区、候选试听与撤销重做
│   ├── arrangement.py     # 分段校验、覆盖与完整排程编译
│   ├── community.py       # 便携工程、HTTP 客户端与本机 Demo 服务
│   ├── community_ui.py    # 共享浏览、发布、下载与异步结果
│   ├── segments.py         # 原曲时间输入解析
│   ├── analysis.py         # 移调候选与适配报告
│   ├── parts.py            # GM 乐器、稳定声部拆分与角色提示
│   ├── track_ui.py         # 共用声部表、多轨工作区与音符总览
│   ├── arranging.py        # 声部八度与旋律/低音优先保留
│   ├── offline_audio.py    # 默认离线转谱、固定资源、任务进程树与保存
│   ├── offline_audio_ui.py # 嵌入式转谱页、ETA、后台任务与结果状态
│   ├── piano_transcription.py # Transkun 2 ONNX 钢琴推理与解码
│   ├── vocal_transcription.py # GAME small 歌声与多乐器预测去重
│   ├── audio_audition.py   # MCI WAV 同位置对照、定位、暂停和循环
│   ├── audio_quality.py    # 已知 MIDI 参考的一对一起音/音高评估
│   ├── notation.py         # MusicXML/MXL、KAR/RMI 统一导入
│   ├── instruments.py      # 乐器键位表
│   ├── keyboard.py         # 前台核对、按键及 UAC 启动
│   ├── local_library.py    # 本地曲名与生成曲谱发现，不含网络访问
│   ├── paths.py            # 资源与用户数据目录
│   ├── diagnostics.py      # 不发送按键的离线发布自检
│   └── assets/             # 图标、帮助、示例 MIDI
├── tests/                  # 自包含离线测试，不使用个人曲谱
├── tools/                  # EXE 构建、离线转谱和验证
├── docs/                   # 使用、结构与发布说明
├── .github/workflows/      # Windows 自动构建
└── releases/               # 本地发布产物，Git 忽略二进制
```

图形应用在创建 Tk 窗口前请求一次 UAC，取消则退出；演奏子进程使用已有管理员令牌普通启动。离线分析、转换、自检和版本命令不提权。源码 GUI 采用 -I 保留已安装的 Pillow；游戏按键子进程使用 -I/-S 与可信 bootstrap，冻结时直接调用 EXE。重启后仍未获得权限会报错退出，不循环弹 UAC。

Pillow 用于界面绘制与角色滑块显示，核心转换和演奏调度继续使用标准库。圆角按钮继承原生 Tk Button，保留焦点、空格触发与禁用语义。主窗采用淡化夜景与四种基础色，分段另用橙色表示已应用；角色头像用于速度滑块及主窗／小窗进度。数值步进在静止时以透明画布显示，编辑时使用原生 Entry，保留键盘与变量同步。背景由 backdrop.py 统一取景，scrolling.py 处理滚动后的内容重绘与分页重新显示，不启用与 Tk 冲突的系统子窗口双缓冲。构建环境、CI 和源码启动显式安装依赖；提权演奏子进程继续保持原有隔离参数。

2.0.2 默认音频入口为原生离线窗口。任务由独立进程及 Windows 作业对象管理，以较低优先级运行；钢琴采用 Transkun 2 ONNX，歌曲采用 GAME small 与 MuScriptor small F16。固定资源清单与 SHA-256 由准备脚本生成，用户包自带完整模型、NumPy／ONNX Runtime、解码器及本机程序。界面按任务队列隔离迟到消息，以选曲变化次数保护当前曲目；停止演奏与取消转谱各自独立。已保存的旧版 MIDI 继续由曲目列表读取。

移调推荐逐一转换 −36 至 +36 的全部 73 个半音，并使用统一 performance_plan 检查实际排程。评分成本为丢音×100＋重合×20＋折回×4＋轮廓反向×8＋音程变形÷12＋混合组×0.15＋延后音数×0.5＋最大延后毫秒÷10；同分优先接近当前移调。轮廓取起音组中的最高原音，只是旋律近似。此算法未分析调性、真实旋律与和声、音色或游戏实际发声；权重是可解释的启发式，音乐质量需要独立试听验证。报告的原曲时间点、原曲总长和演奏时长分别记录，界面只格式化时间显示，JSON 保留秒数。

调度使用一个单调时钟，重复键先松再按，异常与取消后释放自己持有的键。识别 `HTGame.exe` 的可见、无所有者顶层窗口，优先依据 `UnrealWindow` 窗口类，兼容标题为「异环」的原有客户端。找到唯一窗口后锁定窗口句柄和进程 ID，演奏时核对两者与前台焦点。钢琴仅允许程序持有的左 Shift，人工按下的其他修饰键会中止。混合黑白和弦以快速分组适应全局 Shift 状态。

客户端兼容性可参考 [ok-nte 的窗口配置](https://github.com/BnanZ0/ok-nte/blob/main/src/config.py) 和 [Steam 国际服的实测反馈](https://github.com/BnanZ0/ok-nte/issues/313)。各客户端共用同一识别入口。新增客户端时，根据实测进程名与窗口类扩充匹配条件，并覆盖启动器、附属窗口、多个候选及失焦的回归场景。

只读资源与写入目录分开：资源来自包内 assets（EXE 中为 _internal 下的包资源），写入默认位于 %LOCALAPPDATA%\NteMusicDesk。可用 --data-dir 或 NTE_MUSIC_DESK_DATA_DIR 覆盖数据目录，方便离线测试与个人备份。

在线搜索、下载模块与目录快照已移除；界面和命令行只读取主动选择的本地音乐文件。旧版 downloaded_midis 来源侧车仅用于恢复曲名，不访问外部地址。MXL 在内存中校验并读取，拒绝重复、越界、过大或加密的文件；MusicXML 不解析实体或访问外部 DTD。

所有导入最终生成同一 MidiSong 时间化音符模型，复用选轨、演奏与试听。另存 MIDI 以固定速度网格编码秒级音符时刻，面向互通和演奏，不作为保真制谱文档导出。

转换谱保留来源音轨、原曲时间及有限的变更明细。performance_plan 一次生成物理按键事件、计划发声音符和总时长，供键盘执行、时序试听与报告使用；原谱对照另从 MidiSong 合成。音色与游戏输入是否接收仍需实机核对。移调分析和试听在后台执行，过期结果按任务 token 丢弃；停止试听与改变参数会取消合成，开始游戏前取消推荐结果。

演奏方案文件以内容 SHA-256 和乐器命名，带独立 schema；保存前验证设置、曲谱转换与调度。不会把个人绝对路径存入方案，也不把默认用户数据写到源码或内置资源中。

1.3.0 的 MidiSong 将原轨/通道/程序变化拆成稳定虚拟声部，part_sources 保留旧轨映射。方案 v2 保存角色与和弦音数，v1 选择扩展到对应新声部并备份；读取失败的方案不会自动覆盖。批量恢复选轨避免反复绘制。

faithful/balanced 模式保留独立起音，整体八度选择后再处理残余越界，先合并同音再按角色减音。软件每组音数与实际按住键峰值分别报告；钢琴同色音可重叠，遇修饰键切换或重复键提前释放。指标基于计划，不测量游戏声音。

对照试听使用转谱任务准备的 WAV，通过 Windows MCI waveaudio 在同一毫秒位置切换原音频和合成曲谱。更换输入或开始游戏演奏时关闭试听。

playback.py 以单调时钟扣除暂停区间，暂停释放全部键，继续恢复仍处于按住区间的按键，修饰键先于琴键。控制文件带 schema 与递增序号，原子替换；F7 以按下边沿切换。进度直接回报演奏时间，较旧回报不覆盖新的 UI 请求，暂停后不靠系统时间推进游标。游戏失焦和取消检查不放宽。

mini_player.py 只修改本进程小窗：WS_EX_NOACTIVATE、WS_EX_TOOLWINDOW、TOPMOST 和 WM_MOUSEACTIVATE 的 MA_NOACTIVATE，关闭时恢复窗口过程。独立顶层所有权使主窗最小化时保留显示。窗口置顶不代表能够跨越独占全屏或安全桌面；无游戏 DLL 注入或全局鼠标钩子。

工作区由演奏、调整、分段、转谱与社区页面组成。分段以原曲起音时刻归属区间，在同一完整原曲上分别转换候选，再合并并交给统一 performance_plan，避免边界重复长音或影响区外八度选择。全曲设置与分段覆盖共同保存在既有按曲谱哈希／乐器区分的方案中。

分段 A/B 比较使用 `App.start_game_playback`，与整曲演奏共用游戏进程确认、前台切换、倒计时、控制文件及按键释放流程。A 编译已应用方案，B 在设置副本中覆盖候选；完整变体先转换再限制演奏终点，通过原有 `--position` 开始选段，保持区外八度和起点按键状态。转换裁去的片头静音若处于选段内会恢复，以保持 A/B 起始位置一致。临时会话的 offset 将引擎绝对进度／定位与选段相对进度互相转换；比较期间不写整曲续播位置，完成、取消或失败后恢复整曲显示。候选不赋给主曲谱或持久化方案；仅应用操作提交分段。

社区主窗当前仅实例化轻量的 `CommunityPage` 计划占位页，不创建列表、表单、服务或轮询。原 `CommunityDemoPage` 留作后续开发与显式测试，主窗不实例化它；曲目变更通过页面生命周期方法通知，主窗不依赖分享表单字段。

.nteproject 携带原始音符及设置，使用独立 schema 与大小／音符／区间校验，已有工程仍可本地导入。保留的开发 Demo API 为 GET /projects、GET /projects/{sha256}、POST /projects，JSON 响应分别携带 projects、project/id、id；本机服务只绑定 127.0.0.1，按内容哈希保存作品。远程连接要求 HTTPS，Demo 不含账号、内容审核和公开部署。下载回调核对曲目修订号及演奏状态，过期结果保存入库，不强制替换当前曲目。
