# 交互流畅性补充

日期：2026-11-22。此记录针对 2.1.1 归档之后的源码性能改进；已有归档仍是原阶段快照，本次没有重打包或运行全套回归。

## 结果

在同一台 Windows 电脑、同一 Python 环境，以归档 Source ZIP 中的旧实现为参照，测量 1,000×730 窗口、5,000 音及 64 个已保存片段。每次操作计入随后的空闲绘制任务；数据为每场景 3–16 次采样的中位数，反映操作与绘制完成耗时，不等同于屏幕刷新帧率。

| 操作 | 归档实现 | 改进后源码 |
| --- | ---: | ---: |
| 连续选区／游标更新 | 124.64 ms | 2.37 ms |
| 大谱滚动 | 194.06 ms | 40.75 ms |
| 大谱切页 | 130.81 ms | 61.22 ms |
| 全曲设置刷新与保存 | 597.05 ms | 209.90 ms |

首次构建分页仍可能有数百毫秒初始化；电脑负载和窗口大小会造成波动。另补测 1,800×960 窗口，以及真实钢琴转谱任务运行时的大谱交互，各场景的中位数、峰值与负载重叠采样数均保存在机读记录中，不以一次最好成绩承诺任意电脑或任意大小曲谱的响应。

| 补充场景 | 拖选中位数 | 滚动中位数／最大值 | 设置刷新中位数／最大值 |
| --- | ---: | ---: | ---: |
| 1,800×960 窗口 | 2.04 ms | 100.12／264.00 ms | 213.76／245.57 ms |
| 真实钢琴转谱同时运行 | 3.15 ms | 93.21／149.23 ms | 354.27／570.68 ms |

后台测试的大谱拖选、切页、滚动及设置刷新分别有 16、10、16、3 次采样与任务运行重叠；任务成功生成 9 个音符，界面回调未报错。大窗口和后台负载下仍有可感知的短暂停顿，尤其是首次构建页面和整曲设置刷新；这轮改进不代表这些操作已完全无阻塞。

## 改动

- 分段概览按当前曲目、缩放范围、宽度及已应用区间绘制静态图层；拖选仅更新选区和游标，不重建音符或重复排序吸附点。
- 静态音符绘制为最多两张透明图片，绿色与橙色分别表示未调整与已调整。保留所有可见源音符，不再按固定索引间隔抽样，避免周期性音符只显示部分音高。
- 背景装饰裁切到实际可见区域，跳过视口外的图像取样和额外重绘；始终从同一窗口照片取样。局部与全局刷新对同一裁片使用一致的键，静止的视口背景不随滚动反复重建。
- 原生窗口移动与背景更新一起完成布局，再重绘可见内容；保留分页重新显示和异常恢复处理，不重新启用导致黑框的系统子窗口缓冲。
- 按钮仅在文字、字体、留白或最小尺寸改变时重测尺寸；启用状态与配色一次配置，避免每次刷新反复测字和安排布局。
- 已成功完成转换和排程检查的同次设置更新，可将完全相同的曲谱哈希、乐器及参数作为本次保存依据。参数发生变化或独立保存时仍进行完整验证；持久化格式检查始终保留。这不是跨任务缓存，也不跳过失败输入的校验。

## 检查与证据

39 项直接相关的页面、背景、控件、方案恢复与后台转谱检查通过。覆盖裁片像素、滚动前后照片对齐、分页不空白、恢复可见后重绘、区外控件不强制绘制、撤销重做和无效设置不覆盖已保存方案。连续 80 次选区更新后，原生图片和画布项目数量保持不变。另以 2,400 个循环音符确认 12 个音高行均被保留。

实机预览核对了透明概览、橙色标记、固定片段操作区和滚动后的背景，没有观察到黑框。没有向游戏发送演奏按键。

原始记录位于 `.build/validation/2.1.1-responsiveness/`：

- `reference-20261122.json`：已校验归档源代码的参照结果。
- `final-verified-20261122.json`：当前完整音符图层实现的最终常规窗口测量。
- `verified-wide-allnotes-20261122.json`、`verified-busy-allnotes-20261122.json`：当前实现的大窗口与真实后台负载测量。
- `final-targeted-tests.log`、`overview-lanes-tests.log`：局部功能与图层资源检查。
- `measure_ui.py` 和 `profile-*.txt`：本机测量脚本与调用耗时记录。

以以上列出的最终记录为准；早期 `before.json` 的片段终点超出解析后实际曲长，设置刷新结果无效，不能用于对比。后续测量增加了有效方案断言，并使用归档源码重新取得参照。

超大曲谱的首次解析和复杂方案计算仍可能占用主线程；本轮重点减少重复计算和绘制，尚未把所有编辑计算改成后台任务。后续若扩大曲谱规模，应单独测量这些单次操作，并使用曲目修订号保护异步结果。
