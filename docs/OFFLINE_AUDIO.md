# 本地转谱完整包 · v2.0.2

2.0.2 把默认音频入口改为随包携带模型的原生窗口，已将离线开发预览整合进正式版本。既有版本标签与附件保留供回退；2.x 继续使用 `release/2.0.0` 分支。

## 用户操作

下载 **Windows 完整便携包**，完整解压后打开 EXE，点击或拖入“导入音乐”。选择“钢琴曲”或“歌曲／含人声”，点击“开始转谱”。模型、CPU 运行库、音频解码器都在包中，首次使用也无需联网、Python、CUDA、账号或 WebView2。GitHub Code/Source ZIP 是开发源码，不是可直接运行的 Windows 成品。

- **钢琴曲**：Transkun 2 ONNX，保留独立音高、起止与预测力度，不通过高置信度筛选删掉弱音、低音和和弦。
- **歌曲／含人声**：GAME small 识别演唱旋律，MuScriptor small 识别其他声部。演唱旋律单列音轨，同音高且大量重叠的重复预测去重；其他和弦与低音保留。没有做人声分离，密集伴奏、和声、混响和特殊唱法仍可能产生误音。
- 每个歌声任务固定推理种子，便于同一音频、选段、模型与 CPU 后端的结果复现，任务记录保留种子及资源清单校验值。
- 选段默认收起，起点为 0，终点留空至曲末；一次最长处理 60 分钟。短样例更便于先试听。
- 显示真实处理阶段和动态剩余时间范围。整理、保存和试听准备也计入进度，完成保存后才显示完成。
- 更换音频（选择文件、拖入或编辑路径）会清除旧的完成提示、进度、剩余时间和结果入口，并将选段恢复到整首。切换识别类型或修改选段也会清除旧结果展示，已保存的曲谱仍保留。重复选择相同文件、取消文件选择或仅展开选段不会清除有效结果。
- 完成后保存并加入曲目列表，不自动开始游戏演奏。通过“对照试听”在同一时间位置切换原音频与识别曲谱，最多前 30 秒，识别曲谱按**原调、原速**合成，不使用工作台的移调和变速。合成音色不还原原录音音色。
- 原生本地转谱可与主窗／迷你播放器演奏和电脑试听并行。点击“后台运行”收起窗口，从“文件 → 本地音频转谱”查看进度。后台任务完成时只加入曲目列表；如果正在演奏、试听或等待期间换过曲目，也不会自动切换当前曲目。没有这些情况的普通前台任务仍自动载入结果。
- 转谱独立进程以较低调度优先级运行，优先让播放与界面获得 CPU。停止播放不会取消转谱，取消转谱也不会停止播放；同一时间仍只允许一个转谱任务。关闭转谱窗口仍会取消任务，收起请使用“后台运行”。旧轻量／高级音频工具保留原互斥规则。
- 在“调整”页可独奏“演唱主旋律”、选择伴奏声部，再用现有演奏方案适配游戏键位。音频识别 MIDI 与游戏适配结果分开保存。
- 取消或关闭转谱窗口会终止该任务的整个进程树。取消结果不自动导入，也不会因下次扫描进入列表。原音频不会改写或删除。

## 保存与兼容

任务位于 `%LOCALAPPDATA%\NteMusicDesk\offline-transcriptions\<任务ID>`，保留请求、源文件校验值、原始音符、最终 MIDI、对照试听文件及日志。临时解码 PCM 成功后删除。程序资源只读，用户数据不写入安装目录。曲目改名、隐藏和续播设置继续兼容。

旧 Basic Pitch 桌面／浏览器工具及高级 Python 工具保留在“文件 → 其他音频工具”。它们不是默认入口，历史数据和方案无需迁移或删除。

## 体积、硬件与边界

模型约 319 MB，完整资源约 342 MB；以实际 Windows ZIP 和解压后目录的验证报告为准。发布检查同时要求 ZIP 与解压目录都小于十进制 1GB。默认 CPU，不依赖独立显卡；歌曲引擎要求支持 AVX/F16C 的 x64 处理器。推理内存不等于模型文件体积，长录音会使用额外内存与磁盘空间。按段读取与独立进程使关闭任务后可释放模型内存。

Windows 歌曲引擎启用 F16C 硬件转换，保留原 F16 权重和识别精度。歌声模型按顺序运行各模块，释放临时计算缓冲，限制线程数并关闭空闲线程自旋。结果目录的 `result.json` 记录完整耗时、各阶段耗时、实际后端和各进程峰值内存，便于在自己的电脑上复测；不能保证所有硬件、曲长和歌曲复杂度都在相同时间内完成。取消后清理本次临时解码文件，保留原始音频、预测记录和已保存的曲谱。

后台转谱仍会使用 CPU 和内存，其他程序负载较高时转谱可能更久；剩余时间随本机实际进度更新。模拟播放调度验证不等同于游戏实际发声及所有硬件条件下的零影响保证。

钢琴推理按上游分段及解码规则运行，保留预测踏板在原始音符记录；当前 MIDI/游戏接口只导出按键音符，不导出踏板控制。歌曲模型不预测真实力度，采用固定力度。MIDI 半音不能完整表达演唱滑音和颤音；不能保证任意原曲都与原声相同。

模型效果、包装接口一致性和游戏可演奏性分别验证。样例分数与限制见 [离线转谱验证记录](VALIDATION_OFFLINE_AUDIO.md)，不把某个样例的音符数量或端到端跑通当作准确率。

## 构建与回退

开发者安装 `requirements-build.txt`、项目依赖和 Visual Studio C++/CMake 构建工具后，运行：

```powershell
python tools/prepare_offline_audio.py
python -m unittest discover -s tests -v
python tools/check_release.py
python tools/build_windows.py --output .build/current
python tools/verify_release.py --archive .build/current/NTE-Music-Desk-v2.0.2-Windows-x64.zip --report .build/current/verification.json
python tools/package_source.py --output .build/current/NTE-Music-Desk-v2.0.2-Source.zip
python tools/verify_current.py --folder .build/current --report .build/validation/current-identity.json
```

同名输出默认拒绝覆盖；当前工作台和转谱进程应先正常关闭，确需替换才传 `--overwrite`。运行期间先输出到 `.build/cache/` 临时目录，验证后再替换 `.build/current/` 并清理临时展开副本。源码／EXE 一致性检查使用与构建相同版本的 Python。

准备脚本在开发机构建小型本机引擎和仅音频、禁用网络的 LGPL 解码器；固定下载地址、模型版本及 SHA-256 在 `tools/offline_audio/resources.json`。包中提供完整 FFmpeg 对应源码和重编译参数。`verify_offline_audio.py` 可对独立解压的 EXE 指定钢琴／歌曲样例，在 PATH 只有 System32、在线模型访问关闭的条件下验证真实转谱。CI 也先准备完整资源，再打包，禁止静默构建缺少模型的 Windows 包。

模型、编译器缓存和开发环境不提交 Git，也不进入 Source ZIP；源码保留适配器、固定资源清单、构建与验证脚本。所有 2.x 改动仍在 `release/2.0.0`，公开版本标签和旧附件保留供回退。
