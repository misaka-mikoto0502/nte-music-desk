## 音符质量对照

使用已有 CC0 钢琴采样构造的校准短句及其已知 MIDI，按相同音高、起音误差不超过 100 ms 进行一对一匹配。功能通过与质量测量分别记录：

| 样例 | 参考音 | 识别音 | 匹配 | 漏音 | 多余音 | 音高／起音 F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 琶音，均衡版 | 16 | 20 | 16 | 0 | 4 | 88.89% |
| 三和弦，CPU 回退 | 16 | 16 | 15 | 1 | 1 | 93.75% |

这里的 20 音、16 音是当前模型行为的回归预期，不能作为准确率目标。特别是三和弦虽然数量相同，仍存在一处漏音和一处多余音。两个合成短句不足以推断真实歌曲的质量；指标不衡量音色、分离效果、游戏实际发声或主观听感。后续应优先扩大样本和校准误音，而非仅增加输出音数。

## 复现与证据

无需外部音乐或高级模型的样例验证：

```powershell
python -m unittest discover -s tests -v
node tools/light_audio_web/test.mjs
node tools/light_audio_web/test_downloads.mjs
python tools/check_release.py
python tools/check_workflows.py
```

`check_workflows.py` 每次默认创建独立输出目录，保留输入 MXL／多轨 MIDI、96 份转换结果、两份试听 WAV、报告、个人设置夹具和机器可读汇总。指定 `--output` 时需使用新目录。音频推理是可选检查：

```powershell
python tools/check_workflows.py --audio .build/light-cases/arpeggio.wav --expected-notes 20 --reference-midi .build/light-cases/arpeggio.mid
python tools/check_audio_window.py --audio .build/light-cases/triads.wav --without-wasm --expected-notes 16 --output .build/cpu-fallback-new
```

音频命令使用维护者已有校准样例；其生成与测量方式见 [音频基准说明](AUDIO_BENCHMARK.md)。默认样例命令不需要 NumPy、SciPy、模型权重或高级音频环境。

本机完整证据位于 `.build/workflow-validation-20261108/`：

- `baseline-tests.log`：Python 回归输出。
- `final-samples/report.json`：最终样例汇总与实际音频交接；原谱和适配 WAV 位于同目录。
- `audio-reference-comparison.json`：两组音频的参考音符匹配。
- `cpu-fallback/host.json`：实际 CPU 回退、保存与布局记录。
- `frozen-verification.json`：独立解压冻结验证；使用单独报告位置，保留正式 2.0.1 证据。
- `portable/`：独立开发验证包，不作为新正式发布。

构建工具使用 `--output`、`--work` 隔离验证产物；`verify_release.py --report` 可指定独立证据路径。源码打包继续排除 `.build`、个人数据、模型和依赖环境。
